# 检索服务压测：512 / 1024 / 2048 三档

- 日期：2026-10-19
- 目的：补齐改造前那条阶梯里空着的中间三档，看「512 MB 结果缓存 + 向量缓存」的增益随并发怎么变
- 脚本：`stress/scripts/ramp_mixed.py`
- 配置：Redis 512 MB、`QUERY_VEC_ENABLED=true`、`WEB_WORKERS=4`
- **结论：三档 0 错误、0 降级、0 淘汰。吞吐 223.9 / 231.7 / 233.5 req/s，比改造前同档高 29.7% / 47.3% / 49.7%；p50 降到 2.16 / 3.98 / 7.83 s。512 之后吞吐压平在 234 req/s，并发翻四倍不再出吞吐，只出排队。对照结果缓存全命中的理想形态 633 req/s，三档分别到其 35%、37%、37%。**

---

## 1. 口径

| 项 | 值 |
| --- | --- |
| 接口 | `POST /api/v1/reports/search` |
| 总并发 | 64 / 128 / 256 每进程 × 8 进程 = **512 / 1024 / 2048** |
| 每档时长 | 120 s，实测 123 / 126 / 133 s |
| 单请求超时 | 150 s |
| 缓存协议 | 每档开测前只留基础缓存：删 `oirf:report:*` → 固定种子 777 预热 4 000 条 → 校验键数与内存 |
| 词库 | `stress/queries.json`，2 000 条目录，Zipf 抽样 |
| 请求形状 | size 固定 20、page 1–10、session 翻页 80% 停在第一页、mode or 82%、time_weight 70% 不传、时间范围 4 种、版式 12% |
| 唯一变量 | 无。三档同一套配置，只改并发 |

复现：

```powershell
$env:PYTHONIOENCODING='utf-8'; $env:PYTHONPATH=(Get-Location).Path
python stress/scripts/ramp_mixed.py --levels 64,128,256 --procs 8 `
    --duration 120 --tag mid-post --out stress/archive/run/mid-post-512-1024-2048.json
```

## 4. 缓存与编码器

| 档 | 开测前清掉 | 基线 | 命中率 | 淘汰 | 档末键数 |
| --- | --- | --- | --- | --- | --- |
| 512 | 21 239 | 3 252 键 / 54.1 MB | 40.13% | 0 | 19 771 |
| 1024 | 19 771 | 3 252 键 / 54.7 MB | 41.01% | 0 | 20 405 |
| 2048 | 20 405 | 3 252 键 / 54.4 MB | 41.60% | 0 | 21 296 |

三档基线完全一致，档末 2 万键仍远低于 512 MB 的约 3.15 万键容量，所以三档都没有淘汰。

对照改造前：基线 3 190 键 / 53–55 MB，命中率 35.1 / 34.6 / 35.2%，512 档淘汰 136、2048 档淘汰 74。

编码器与向量表：

- `query_vec` 全程 1 996 → 1 996 行，一行没涨。
- 一次编码必写一行，行数不动 ⇒ 三档加三轮预热，编码器调用为 0。
- api 容器无重启，日志无 5xx、无异常栈，`degraded` 三档均为 0。

## 5. 事实

1. 吞吐 223.9 → 231.7 → 233.5，512 之后基本不动，平台约 234 req/s。
2. p50 随并发翻倍近似线性：2.16 → 3.98 → 7.83 s。吞吐不涨而延迟翻倍，说明已经是纯排队。
3. 2048 档 25% 的请求超过 10 s，但没有错误、没有降级、没有重启。
